Multilingual UI regression testing on a demo recreation-centre booking flow. 24 realistic UI defects and 8 harmless restyles were seeded one at a time, then each strategy was run at 320, 360, 412px phone widths. Generated 2026-10-15 17:25 from 594 page loads in 113.1s.

What I expected, and what happened

  • English-only testing missed 9 of 24 defects. 8 of them were layout bugs that only show up once text is longer than English, and other strategies caught them. The last one was missed by everything (see Limitations).
  • My hypothesis was that real scripts would catch bugs nothing else could. On this test set they didn't. No defect was caught only by a real language. Pseudo-localisation, the cheap industry shortcut, caught 23 with 6 page loads per release, against 22 for real languages with 15.
  • Tamil did almost all of the real-language work (22/24 on its own), because its words are much longer than the English source. Chinese and Thai, which are often shorter, caught fewer defects than English.
  • Practical recommendation: run English and pseudo-localisation on every build, since that pair caught every defect any strategy caught. Keep Tamil as one real-script check, because pseudo-localisation only stretches Latin text and cannot reproduce script-specific problems that this test set did not include.

Limitations

  • I wrote both the defects and the checks. The defects follow common real-world CSS regressions and were fixed before the first run, but results on a real app's history of bugs could differ.
  • The checker itself had a bug. Version 1 skipped overlaps inside fixed bars, so it missed D15 (tab labels running into each other). I fixed it after seeing the miss, which means the version 2 scores are slightly optimistic. Version 1 scores were 15, 22 and 21 of 24.
  • D08 was missed by every strategy. The summary rows stopped wrapping, but none of the translated values were long enough to overflow, so there was no visible symptom to catch. It is a latent bug, not a detected one.
  • Translations are machine-generated and unreviewed. String length and glyph height are realistic, but the wording is placeholder text.
  • Some problems are invisible to these checks. In the clean Tamil build, a long bottom-tab label breaks in the middle of a word. Nothing overflows, so no check fires, but a native reader would notice. Catching that needs a line-break check or a human review.
  • One demo page, Chromium only, three phone widths. No real devices, no iOS Safari, no user data. The demo is not affiliated with any agency.
  • Clean-baseline findings: 0 across all languages and widths, so every flagged item above is caused by the seeded change.
